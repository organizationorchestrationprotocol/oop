# Maintainer reference mechanisms

Technical audit instructions and the DIAGNOSE, PREPARE, VERIFY, APPLY and REPORT commands live in [the repository maintainer appendix](../PROTOCOL.md#rules-for-the-maintainer); see the [maintainer command guidance](../README.md#maintainer-commands).

Optional maintainer-only report validation: `node tools/validate-maintainer-report.mjs <local-report.md>`; focused regressions: `node --test tools/validate-maintainer-report.test.mjs`. The read-only CLI supports English/Italian ATX headings, consecutive numbered PROP entries and six bold labeled fields, with labeled independent impact lines. It ignores fenced examples and returns PASS, FAIL or UNSUPPORTED (nonzero for the latter two). Other languages or presentation forms remain NOT VERIFIED, never requiring a language change. PASS covers structure and declared consistency only; no chat interceptor is installed. Reviewable semantic PREPARE/VERIFY scenarios and contract-move traceability are in [maintainer-report-scenarios.md](maintainer-report-scenarios.md). These tests run in a distinct early CI step, separate from the producer observations, with no consumer hook or acceptance inventory change.

Appendix disclosure depends on declared edits, never on a filename mention. In the impact field, the optional `Edited region:` / `Regione modificata:` accepts `runtime-only`, `maintainer-appendix-only`, `runtime+maintainer-appendix` or `reference-only`. An appendix role requires a separate physical maintainer appendix edit `REQUIRED` disclosure; clear legacy appendix disclosures remain supported. Runtime roles require source `REQUIRED`; appendix-only/reference-only roles require both normative operations `NOT REQUIRED`. Within scope/after fields, affirmative `edit/modify/update/change/add/remove the maintainer appendix` and Italian `modifica/aggiorna/aggiunge/rimuove appendice maintainer` (including documented infinitives and articles) also require disclosure and reject a contradictory role. This bounded phrase profile cannot infer arbitrary natural-language intent, distinguish every negation/quotation, or verify actual edits. Filename references alone impose no appendix requirement; unsupported prose intent remains a semantic review responsibility.

The complete current-source derived distribution is generated with `node tools/generate-release.mjs`, then accepted locally with `node tools/accept-release.mjs`. The generator exports 36 modules and 55 complete source clauses from an explicit semantic allocation; BOOT-01–13 and lifecycle/interface records formalize execution boundaries without replacing semantic judgment. It stages every output in memory, validates source/schema/dependencies and the complete inventory, then preflights every output path and orphan before any filesystem mutation. Shared path checks reject traversal, symlinks/junctions, non-directory parents, non-file outputs and unsafe JSON orphans. Only obsolete JSON files directly inside `distribution/modules/` and `distribution/details/` are removed; unrelated files are preserved. Producer acceptance runs 96 expected local observations (69 retained, nine REL-ORG cases, ten REL-ROUTE cases and eight efficiency regression cases) and seven scenarios against the actual package. See `evidence/release-traceability.json` and the acceptance reports described below for scope and limitations. These commands never belong in consumer bootstrap and perform no provider effects or runtime installation.

Routing wire format 1 is the historical layout with descriptor-local `modules[].facets`; wire format 2 is compact and omits those duplicate arrays. The complete ordered `routing.facets` map is authoritative, with dependencies and exact detail references retained. Consumers must inspect the supported format and resolve facets through that map; unsupported formats, conflicting maps and broken references must fail closed. Reviewed allocation facets and detail triggers remain intact. REL-ROUTE-007 independently reads pinned historical format 1 and current format 2 fixtures and checks equivalent closure across all six input dimensions, unions and unknown classification; this is no installed adapter or evidence that external readers requiring descriptor-local facets work. Such readers must upgrade or supply an appropriately verified adapter. `routing.format` describes structure only; the full OOP Git commit identifies the revision, and neither routing nor format grants authority or establishes consumer adoption. This changes no canonical runtime rule and does not relax the rolling efficiency gate.

The required `local-tests` CI job runs for the existing public pull-request and main-push events. Its first step fails for private or unconfirmed visibility before checkout or tests, instead of satisfying the required check through a job-level skip. Review publication rules and billing exposure before any visibility change. Standard GitHub-hosted public CI is free under [GitHub's policy](https://docs.github.com/en/billing/concepts/product-billing/github-actions); a private fail-fast job still requests a runner and can consume private minutes or incur overage charges. No private run, paid minutes or future zero-cost guarantee is authorized by these checks; private provider behavior is NOT VERIFIED and costs are not_measured. A hard no-charge private policy needs a separately approved zero-cost fail-closed mechanism before changing visibility.
